# Connect Dual Spark для Unsloth Studio

Connect Dual Spark автоматически находит прямое соединение ConnectX-7 между двумя NVIDIA DGX Spark, устанавливает Unsloth Studio и настраивает `llama.cpp` RPC на втором Spark. Межузловой модельный трафик разрешается только через проверенный высокоскоростной интерфейс ConnectX-7.

> **Статус предварительной версии:** проект проходит автоматические статические проверки и проверки структуры пакетов, но полная чистая установка на физической паре DGX Spark ещё не проверена. Считайте версию 0.4.0 предварительной и протестируйте её на целевом оборудовании перед использованием в рабочей среде.

## Что потребуется

- Ровно два NVIDIA DGX Spark с Ubuntu ARM64.
- Физический QSFP-кабель между портами ConnectX-7 обоих Spark.
- Кластер, заранее настроенный через [NVIDIA Sync Cluster Assistant](https://docs.nvidia.com/sync/latest/cluster-assistant.html).
- Беспарольный SSH между узлами. Установщик определяет адрес и пользователя второго Spark автоматически; вводить их вручную не нужно.
- Доступ в интернет для загрузки Unsloth и исходников `llama.cpp`.
- Графический сеанс GNOME и GNOME Terminal для установщика и просмотра журнала. Сам worker RPC работает системной службой независимо от окна терминала и входа пользователя.
- Если Studio уже загружает модель через `llama-server`, сначала выгрузите её. Установщик запускает отдельную небольшую пробную модель и не прерывает текущий сеанс.

Во время установки система может запросить пароль `sudo` или подтверждение ОС на локальном либо втором Spark. Это отдельная системная авторизация; пароль для SSH между узлами запрашиваться не должен.

Файл `.run` сам устанавливает недостающие базовые сетевые утилиты через Ubuntu APT. Предварительно устанавливать пакет `.deb` не требуется.

## Быстрый запуск одного файла с рабочего стола

Скачайте один файл `Connect-Dual-Spark-arm64.run` из раздела [GitHub Releases](https://github.com/grosa787/connect-dual-spark-for-unsloth-studio/releases) на рабочий стол основного DGX Spark. Дополнительный каталог с исходниками рядом не нужен.

При желании сначала проверьте встроенный архив:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --verify
```

Запустите установщик на русском языке:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --lang ru
```

Чтобы явно выбрать английский язык, выполните:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --lang en
```

Значение `--lang auto` (также используемое по умолчанию) сначала проверяет `CONNECT_DUAL_SPARK_LANG=ru` или `en`, а затем системную локаль. Локали, начинающиеся с `ru`, включают русский язык; все остальные — английский. Явный параметр `--lang ru` или `--lang en` имеет приоритет. Значение `CONNECT_DUAL_SPARK_LANG=auto` оставляет выбор локали.

Файл проверит встроенную контрольную сумму, распакует Python-модули во временный закрытый каталог и откроет GNOME Terminal. Временные файлы удаляются после закрытия окна установщика. Файл `.run` предназначен для Ubuntu ARM64 и не содержит адресов, имён пользователей или учётных данных.

Если GNOME Terminal или графический сеанс недоступны, launcher выводит понятную ошибку. Во время установки в отдельном окне показывается журнал RPC; закрытие этого окна не остановит службу.

## Запуск из исходников для разработки

Файл `Connect-Dual-Spark.run` должен находиться рядом с каталогом `dual_spark`. В клонированном репозитории запустите:

```bash
./Connect-Dual-Spark.run --lang ru
```

Откроется отдельное окно GNOME Terminal, и из корня проекта выполнится:

```bash
python3 -m dual_spark.cli --lang ru install
```

Исходный launcher предназначен для разработки и требует каталог `dual_spark` рядом. Собранный описанным ниже способом release-файл является самостоятельным.

## Сборка самостоятельного release-файла `.run`

```bash
./scripts/build_run.sh 0.4.0
./dist/Connect-Dual-Spark-arm64.run --verify
```

Сценарий включает текущий пакет `dual_spark`, удаляет кэш Python, добавляет SHA-256 встроенного архива и создаёт `dist/Connect-Dual-Spark-arm64.run`. Если аргумент версии не указан, используется текущая версия пакета.

## Сборка и установка пакета `.deb`

Пакет собирается для архитектуры `arm64`:

```bash
./scripts/build_deb.sh 0.4.0
sudo apt install ./dist/connect-dual-spark_0.4.0_arm64.deb
```

После установки запустите **Connect Dual Spark** из меню приложений или выполните:

```bash
connect-dual-spark --lang ru install
```

## Этапы установки

Терминальный интерфейс последовательно показывает состояние каждого этапа:

1. Проверка ОС, архитектуры и необходимых системных команд.
2. Поиск активного ConnectX-7 и единственного подходящего второго Spark.
3. Проверка скорости линка, прямого маршрута в обе стороны и беспарольного SSH.
4. Установка Unsloth Studio и сборка локального `llama-server` из управляемого клона `unslothai/llama.cpp` на основном Spark.
5. Синхронизация того же исходного дерева через ConnectX-7 и сборка `llama.cpp` RPC на втором Spark.
6. Установка системной службы RPC с автозапуском при загрузке до входа пользователя.
7. Защита стандартного и управляемого путей к `llama-server`, затем пробный запуск небольшой GGUF-модели через обёртку с размещением весов на втором Spark и подтверждением активного RDMA.
8. Настройка Studio и итоговая проверка установки.

Предложение запустить Unsloth Studio появляется только после успешного завершения всех этапов. При ошибке процесс останавливается с диагностикой и не переключает RPC на другой сетевой интерфейс.

## Команды и язык интерфейса

```bash
connect-dual-spark --lang ru install
connect-dual-spark --lang ru check
connect-dual-spark --lang ru start-rpc
connect-dual-spark --lang ru studio
connect-dual-spark --lang ru status
```

- `install` выполняет полную настройку и после проверок предлагает запустить Studio.
- `check` только проверяет окружение, линк, маршрут и SSH; пакеты и конфигурация не изменяются.
- `start-rpc` проверяет системную службу RPC, при необходимости запускает её и открывает окно журнала.
- `studio` проверяет текущий CX7 и конфигурацию RPC, затем запускает настроенную службу Studio. Используйте эту команду после установки, в том числе из того же терминала, где шёл установщик.
- `status` показывает состояние линка, RPC и конфигурации Studio.

`--lang ru` принудительно включает русский язык, `--lang en` — английский, а `--lang auto` сначала проверяет `CONNECT_DUAL_SPARK_LANG`, затем системную локаль. Параметр работает до или после команды, например `connect-dual-spark status --lang en`. Если он не задан, применяется автоматический выбор. Эта настройка локализует собственные подсказки, прогресс и статусы установщика; диагностика от системных команд и сторонних инструментов может оставаться на английском языке.

После восстановления питания RPC второго Spark запускается автоматически как системная служба `connect-dual-spark-rpc.service` с `WantedBy=multi-user.target` и `Restart=always`; вход пользователя на втором Spark не нужен. На основном Spark проверьте состояние командой `connect-dual-spark status` и при необходимости запустите Studio командой `connect-dual-spark studio`. Если питание пропало во время работы модели, после восстановления соединения модель может потребовать повторной загрузки.

Переменные окружения для обычных новых терминалов также сохраняются в `.bashrc` и `environment.d`. Повторный `install` проверяет и восстанавливает ту же управляемую конфигурацию; он не выполняет `git pull` и не обновляет версии исходников автоматически.

Для загрузки GGUF-моделей установщик размещает автономную защитную обёртку в стандартном пути Unsloth к `llama-server` (`~/.unsloth/llama.cpp/llama-server`) и в управляемом пути Connect Dual Spark (`~/.local/share/connect-dual-spark/llama-src/llama-server`). Поэтому защита действует и при внешнем запуске Studio через API, когда процесс не наследует `LLAMA_ARG_RPC`. Перед запуском модели обёртка требует доступности найденного маршрута ConnectX-7 и worker RPC на порту `50053`. При опросе `--list-devices` она показывает оба устройства — `CUDA0` и `RPC0`. При загрузке модели она добавляет в конец итоговой команды `llama.cpp` следующие параметры, поэтому они переопределяют конфликтующий выбор устройств:

```text
--rpc discovered-peer:50053 --device CUDA0,RPC0 --split-mode layer --tensor-split 1,1 --n-gpu-layers all
```

Если проверенный маршрут или worker недоступен, обёртка запрещает загрузку модели вместо запуска GGUF только на основном Spark. Она также отклоняет параметры размещения `-ot` / `--override-tensor`, которые могли бы закрепить все веса за одним устройством. Защита распространяется на GGUF-инференс через `llama-server` в указанных выше стандартном и управляемом путях. Явно выбранный альтернативный бинарный файл или другой бэкенд обходит эту защиту. Если обновление Unsloth заменит одну из защитных символических ссылок, снова выполните `connect-dual-spark install`, чтобы восстановить защиту до следующей загрузки модели.

## Гарантия маршрута через ConnectX-7

Установщик не принимает адрес из Wi-Fi, обычного Ethernet или управляющей сети. Он выбирает только активный ConnectX-7 с приватным IPv4-адресом и согласованной скоростью не ниже 100 Гбит/с, а затем проверяет исходящий и обратный маршруты.

RPC привязывается к адресу ConnectX-7 второго Spark, а Studio получает именно этот адрес через `LLAMA_ARG_RPC`. Установщик задаёт `UNSLOTH_LLAMA_CPP_PATH` для собранного локального `llama.cpp`, а `LLAMA_SERVER_PATH` — для защищённого бинарного файла в службе Studio, shell и `environment.d`. Защищённые стандартный и управляемый пути к `llama-server` принудительно задают тот же endpoint даже без этих переменных окружения. Если проверенный маршрут исчезает, установка, проверка или защищённая загрузка модели завершается ошибкой; автоматического перехода модельного трафика на медленную сеть или запуска только на основном Spark нет. Интернет-загрузки и другой внешний трафик могут продолжать использовать обычное подключение.

RPC-протокол `llama.cpp` не следует выставлять в публичную или недоверенную сеть. Оставляйте подсеть ConnectX-7 изолированной и не публикуйте RPC-порт на управляющих интерфейсах.

## Если проверка не проходит

Запустите `connect-dual-spark check` и устраните первую показанную ошибку. Обычно нужно проверить посадку QSFP-кабеля, повторить настройку кластера через NVIDIA Sync и убедиться, что беспарольный SSH работает между двумя узлами. Установщик намеренно не просит вручную вводить адрес или имя пользователя и останавливается, если на линке найдено больше одного подходящего узла.
