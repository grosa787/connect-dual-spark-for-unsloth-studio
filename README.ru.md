# Connect Dual Spark для Unsloth Studio

Connect Dual Spark автоматически находит прямое соединение ConnectX-7 между двумя NVIDIA DGX Spark, устанавливает Unsloth Studio и настраивает `llama.cpp` RPC на втором Spark. Межузловой модельный трафик разрешается только через проверенный высокоскоростной интерфейс ConnectX-7.

> **Статус предварительной версии:** для версии 0.6.0 получены результаты fastload на эталонной паре DGX Spark, и проект проходит автоматические проверки, но полную чистую установку этого выпуска на физическом оборудовании ещё нужно проверить. Протестируйте предварительную версию на целевой паре перед использованием в рабочей среде.

Автономная работа доступна только после успешной установки и сопряжения двух Spark. Для первоначальной установки по-прежнему нужны обе системы и прямое соединение ConnectX-7 между ними. В дальнейшем, если ни на одном локальном интерфейсе ConnectX-7 нет несущей, защищённый `llama-server` может работать только на основном Spark, а Unsloth/`llama.cpp` определит, как разместить модель в доступной локальной памяти. Это не гарантирует, что модель, рассчитанная на два Spark, поместится на одном.

## Что потребуется

- Ровно два NVIDIA DGX Spark с Ubuntu ARM64. Оба обязательны для первоначальной установки и сопряжения.
- Физический QSFP-кабель между портами ConnectX-7 обоих Spark.
- Кластер, заранее настроенный через [NVIDIA Sync Cluster Assistant](https://docs.nvidia.com/sync/latest/cluster-assistant.html).
- Беспарольный SSH между узлами. Установщик определяет адрес и пользователя второго Spark автоматически; вводить их вручную не нужно.
- Доступ в интернет для загрузки Unsloth и исходников `llama.cpp`.
- Графический сеанс GNOME и GNOME Terminal для установщика и просмотра журнала. Сам worker RPC работает системной службой независимо от окна терминала и входа пользователя.
- Если Studio уже загружает модель через `llama-server`, сначала выгрузите её. Установщик запускает отдельную небольшую пробную модель и не прерывает текущий сеанс.

Во время установки система может запросить пароль `sudo` или подтверждение ОС на локальном либо втором Spark. Это отдельная системная авторизация; пароль для SSH между узлами запрашиваться не должен.

Файл `.run` сам устанавливает недостающие базовые сетевые утилиты через Ubuntu APT. Предварительно устанавливать пакет `.deb` не требуется.

## Быстрый запуск одного файла с рабочего стола

Скачайте один файл `Connect-Dual-Spark-arm64.run` из раздела [GitHub Releases](https://github.com/grosa787/connect-dual-spark-for-unsloth-studio/releases) на рабочий стол основного DGX Spark. Дополнительный каталог с исходниками рядом не нужен.

При желании сначала проверьте встроенный архив:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --verify
```

Запустите установщик на русском языке:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --lang ru
```

Чтобы явно выбрать английский язык, выполните:

```bash
bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" --lang en
```

Значение `--lang auto` (также используемое по умолчанию) сначала проверяет `CONNECT_DUAL_SPARK_LANG=ru` или `en`, а затем системную локаль. Локали, начинающиеся с `ru`, включают русский язык; все остальные — английский. Явный параметр `--lang ru` или `--lang en` имеет приоритет. Значение `CONNECT_DUAL_SPARK_LANG=auto` оставляет выбор локали.

Файл проверит встроенную контрольную сумму, распакует Python-модули во временный закрытый каталог и откроет GNOME Terminal. Временные файлы удаляются после закрытия окна установщика. Файл `.run` предназначен для Ubuntu ARM64 и не содержит адресов, имён пользователей или учётных данных.

Если GNOME Terminal или графический сеанс недоступны, launcher выводит понятную ошибку. Во время установки в отдельном окне показывается журнал RPC; закрытие этого окна не остановит службу.

## Запуск из исходников для разработки

Файл `Connect-Dual-Spark.run` должен находиться рядом с каталогом `dual_spark`. В клонированном репозитории запустите:

```bash
./Connect-Dual-Spark.run --lang ru
```

Откроется отдельное окно GNOME Terminal, и из корня проекта выполнится:

```bash
python3 -m dual_spark.cli --lang ru install
```

Исходный launcher предназначен для разработки и требует каталог `dual_spark` рядом. Собранный описанным ниже способом release-файл является самостоятельным.

## Сборка самостоятельного release-файла `.run`

```bash
./scripts/build_run.sh 0.6.0
./dist/Connect-Dual-Spark-arm64.run --verify
```

Сценарий включает текущий пакет `dual_spark`, удаляет кэш Python, добавляет SHA-256 встроенного архива и создаёт `dist/Connect-Dual-Spark-arm64.run`. Если аргумент версии не указан, используется текущая версия пакета.

## Сборка и установка пакета `.deb`

Пакет собирается для архитектуры `arm64`:

```bash
./scripts/build_deb.sh 0.6.0
sudo apt install ./dist/connect-dual-spark_0.6.0_arm64.deb
```

После установки запустите **Connect Dual Spark** из меню приложений или выполните:

```bash
connect-dual-spark --lang ru install
```

## Этапы установки

Терминальный интерфейс последовательно показывает состояние каждого этапа:

1. Проверка ОС, архитектуры и необходимых системных команд.
2. Поиск активного ConnectX-7 и единственного подходящего второго Spark.
3. Проверка скорости линка, прямого маршрута в обе стороны и беспарольного SSH.
4. Установка Unsloth Studio и сборка версионного fastload-варианта `llama-server` из официально установленных исходников `llama.cpp` на основном Spark.
5. Синхронизация этих же пропатченных исходников через ConnectX-7 и сборка соответствующего версионного RPC worker на втором Spark.
6. Установка системной службы RPC с автозапуском при загрузке до входа пользователя.
7. Защита стандартного и управляемого путей к `llama-server`, затем пробный запуск небольшой GGUF-модели через обёртку с размещением весов на втором Spark и подтверждением активного RDMA.
8. Настройка Studio и итоговая проверка установки.

Предложение запустить Unsloth Studio появляется только после успешного завершения всех этапов. При ошибке процесс останавливается с диагностикой и не переключает RPC на другой сетевой интерфейс.

## Команды и язык интерфейса

```bash
connect-dual-spark --lang ru install
connect-dual-spark --lang ru check
connect-dual-spark --lang ru start-rpc
connect-dual-spark --lang ru studio
connect-dual-spark --lang ru refresh
connect-dual-spark --lang ru update-unsloth
connect-dual-spark --lang ru status
```

- `install` выполняет полную настройку и после проверок предлагает запустить Studio.
- `check` только проверяет окружение, линк, маршрут и SSH; пакеты и конфигурация не изменяются.
- `start-rpc` проверяет системную службу RPC, при необходимости запускает её и открывает окно журнала.
- `studio` запускает настроенную службу Studio после проверки пары либо сохранённой автономной настройки, когда кабель ConnectX-7 не активен.
- `refresh` согласует быструю загрузку после обновления Unsloth из командной строки или пропущенного фонового восстановления.
- `update-unsloth` останавливает управляемую Studio без активной модели, запускает официальный updater Unsloth, пересобирает согласованную fastload-пару и вновь запускает Studio.
- `status` показывает, работает Spark в паре или автономно, а также состояние RPC и конфигурации Studio.

Пакет `.deb` устанавливает команду `connect-dual-spark`. Если используется один файл `.run`, те же команды указываются после его пути, например `bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" refresh` или `bash "$(xdg-user-dir DESKTOP)/Connect-Dual-Spark-arm64.run" update-unsloth`.

`--lang ru` принудительно включает русский язык, `--lang en` — английский, а `--lang auto` сначала проверяет `CONNECT_DUAL_SPARK_LANG`, затем системную локаль. Параметр работает до или после команды, например `connect-dual-spark status --lang en`. Если он не задан, применяется автоматический выбор. Эта настройка локализует собственные подсказки, прогресс и статусы установщика; диагностика от системных команд и сторонних инструментов может оставаться на английском языке.

После восстановления питания RPC второго Spark запускается автоматически как системная служба `connect-dual-spark-rpc.service` с `WantedBy=multi-user.target` и `Restart=always`; вход пользователя на втором Spark не нужен. На основном Spark проверьте состояние командой `connect-dual-spark status` и при необходимости запустите Studio командой `connect-dual-spark studio`. Если питание пропало во время работы модели, после восстановления соединения модель может потребовать повторной загрузки.

Переменные окружения для обычных новых терминалов также сохраняются в `.bashrc` и `environment.d`. Повторный `install` проверяет и восстанавливает ту же управляемую конфигурацию; он не выполняет `git pull` и не выбирает неопубликованную ревизию исходников.

Для загрузки GGUF-моделей установщик задаёт `LLAMA_SERVER_PATH` на защитную ссылку в текущем управляемом корне Unsloth. Сама обёртка и версионные fastload-выпуски находятся в `~/.local/share/connect-dual-spark`, вне дерева, которое заменяет официальное обновление Unsloth. Studio использует защищённый путь при запусках из интерфейса и через внешний OpenAI-совместимый API. Явно выбранный другой бинарный файл или иной backend не входит в область действия этой интеграции.

## Быстрая загрузка и обновления Unsloth

В режиме пары обёртка выбирает DirectIO (`--load-mode dio`), разрешает согласование RDMA и включает опциональный путь `GGML_RPC_NO_HASH_CACHE=1` в пропатченном RPC-клиенте основного узла. При этом сохраняются проверенный приватный endpoint ConnectX-7, устройства `CUDA0,RPC0` и распределение 1:1. На worker переменная обхода кэша не включается.

На эталонной паре DeepSeek V4 Flash Vision Q8 (150,75 GiB, контекст 1 048 576, распределение 1:1) достигла состояния готовности за 5 мин 35,6 с со штатным TCP-загрузчиком. Один RDMA дал 5 мин 35,5 с, один DirectIO — 3 мин 32,3 с. Сочетание DirectIO, отключения хэширования RPC-кэша на основном узле и RDMA дало 112,3 с в двух запусках и 110,2 с через защитную обёртку Studio. Это сравнение на протестированной системе, а не фиксированный порог для других моделей или машин.

После официальной установки новой управляемой версии `llama.cpp` Connect Dual Spark определяет установленный выпуск и заново собирает основной узел и worker из его исходников. Сборки сохраняются как новая версионная пара вне заменяемого дерева Unsloth. Встроенный updater `llama.cpp` сначала запускает официальный установщик, затем синхронно обновляет пару. Обновления из командной строки обнаруживает служба восстановления, а перед следующим запуском модели в режиме пары выполняется дополнительная проверка. Поэтому первый запуск в режиме пары после обновления может ожидать однократной сборки основного узла и worker.

Для полного обновления Studio выгрузите текущую модель и выполните `connect-dual-spark update-unsloth`. Собственный CLI-updater Unsloth требует, чтобы управляемая Studio была остановлена; эта команда останавливает и запускает службу вокруг официального обновления. Если обновляете напрямую через `unsloth studio update`, сначала остановите Studio, затем выполните `connect-dual-spark refresh` перед её запуском.

Встроенный updater `llama.cpp` в текущей Studio ограничивает общий срок официальной загрузки и двух сборок fastload 30 минутами. Если медленная загрузка превысит этот срок, интерфейс может сообщить об ошибке уже после замены официальных файлов. Обёртка не запустит устаревшую пару; завершите согласование командой `refresh` из файла `.run` или CLI. На эталонной паре сборка под установленную версию заняла около 12 минут.

Фоновое восстановление не останавливает активную модель. Переключение на новую собранную пару ждёт, пока модель перестанет использовать worker. Если новый исходный код RPC больше не соответствует поддерживаемому узкому патчу или основной узел и worker нельзя подтвердить как одну пару, новый запуск на паре завершается явной ошибкой восстановления вместо незаметного использования старого fastload-движка. Для будущих изменений исходников upstream может потребоваться новый выпуск Connect Dual Spark.

После первоначальной установки на двух Spark обёртка выбирает один из двух режимов работы:

- Если хотя бы на одном локальном интерфейсе ConnectX-7 есть несущая, а worker RPC на порту `50053` доступен через проверенный маршрут, при опросе `--list-devices` обёртка показывает оба устройства — `CUDA0` и `RPC0`. Перед загрузкой модели она удаляет прежние параметры RPC, устройств, распределения и режима загрузки, включая устаревший RPC-адрес в медленной сети. Затем задаёт только проверенный адрес ConnectX-7 и следующие параметры для распределения 1:1, а после них — `--load-mode dio`:

```text
--rpc discovered-peer:50053 --device CUDA0,RPC0 --split-mode layer --tensor-split 1,1 --n-gpu-layers all --load-mode dio
```

- Если ни на одном локальном интерфейсе ConnectX-7 нет несущей или [NIC ConnectX-7 исчезли из системы без кабеля из-за hotplug](https://forums.developer.nvidia.com/t/the-100g-network-interface-card-nic-is-not-visible-in-the-operating-system/367149), обёртка переходит в автономный режим по сохранённой настройке пары. Перед запуском локального `llama-server` она удаляет аргументы RPC, настройки устройства и распределения, оставшиеся от режима двух Spark, а также связанные с ними настройки окружения. Принудительное распределение 1:1 не применяется: Unsloth/`llama.cpp` сам определяет, что помещается в локальной памяти основного Spark. Слишком большая модель всё равно может не загрузиться.

Режим выбирается при запуске модели. После отключения кабеля выгрузите и загрузите заново модель, которая работала на паре, чтобы перейти на один Spark; после подключения кабеля так же перезагрузите автономную модель, чтобы распределить её между двумя Spark. После обновления пакета без кабеля команда `connect-dual-spark studio` восстановит обёртку из сохранённой настройки пары перед запуском Studio; первичная установка всё равно требует оба Spark.

Если хотя бы на одном локальном интерфейсе ConnectX-7 есть несущая, но проверенный маршрут или worker RPC недоступен, обёртка действует по принципу fail closed и запрещает загрузку модели. Это исключает незаметный локальный запуск, когда кабель выглядит подключённым, и передачу модельного трафика через другую сеть. В подключённом режиме обёртка также отклоняет параметры размещения `-ot` / `--override-tensor`, которые могли бы закрепить все веса за одним устройством. Если обновление заменит управляемую защитную ссылку, служба восстановления и проверка при запуске восстановят её до выбора соответствующей fastload-пары.

## Гарантия маршрута через ConnectX-7

Установщик не принимает адрес из Wi-Fi, обычного Ethernet или управляющей сети. Он выбирает только активный ConnectX-7 с приватным IPv4-адресом и согласованной скоростью не ниже 100 Гбит/с, а затем проверяет исходящий и обратный маршруты.

RPC привязывается к адресу ConnectX-7 второго Spark, а Studio получает именно этот адрес через `LLAMA_ARG_RPC`. Установщик задаёт `UNSLOTH_LLAMA_CPP_PATH` для официальных управляемых исходников, а `LLAMA_SERVER_PATH` — для защищённого пути в службе Studio, shell и `environment.d`. Обёртка принудительно использует тот же проверенный endpoint, даже если запрос запуска передаёт конфликтующие параметры размещения. Для установки и проверки всегда нужен подтверждённый маршрут между двумя Spark. После установки запуск только на основном узле разрешён, лишь когда ни на одном локальном интерфейсе ConnectX-7 нет несущей; если несущая есть хотя бы на одном из них, отсутствие проверенного маршрута или worker остаётся ошибкой. Модельный трафик никогда не переключается на более медленную сеть. Интернет-загрузки и другой внешний трафик могут продолжать использовать обычное подключение.

RPC-протокол `llama.cpp` не следует выставлять в публичную или недоверенную сеть. Оставляйте подсеть ConnectX-7 изолированной и не публикуйте RPC-порт на управляющих интерфейсах.

Studio слушает порт 8888 на всех интерфейсах хоста, чтобы с другого ноутбука можно было обращаться к её интерфейсу и API с авторизацией. Ограничьте доступ к этому порту доверенной локальной сетью или VPN через межсетевой экран; не пробрасывайте его в публичный интернет.

## Если проверка не проходит

Запустите `connect-dual-spark check` и устраните первую показанную ошибку. Обычно нужно проверить посадку QSFP-кабеля, повторить настройку кластера через NVIDIA Sync и убедиться, что беспарольный SSH работает между двумя узлами. Ошибка восстановления fastload после обновления Unsloth также может означать, что новый официальный исходный код RPC изменился сильнее, чем допускает патч этого выпуска Connect Dual Spark; обновите Connect Dual Spark перед повторным запуском на паре. Установщик намеренно не просит вручную вводить адрес или имя пользователя и останавливается, если на линке найдено больше одного подходящего узла.
