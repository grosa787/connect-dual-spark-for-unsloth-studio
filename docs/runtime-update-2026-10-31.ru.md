# Обновление среды — 31 октября 2026 года

Обновлено и проверено на имеющейся паре DGX Spark с Ubuntu 24.04 ARM64. Studio, RPC и служба отслеживания обновлений активны и включены для автозапуска. После тестов модель выгружена.

| Компонент | До обновления | Обновлённая установка |
| --- | --- | --- |
| Unsloth / unsloth_zoo | 2026.10.9 | 2026.10.11 |
| llama.cpp от Unsloth | b11876-mix-ec42614 | b11985-mix-c116c32 |
| Коммит исходников | 468ad5824c4afb245338f0ede29ef31680ba59c7 | 6f4cc4d72556554a7c137de536e2fbd93fd7f907 |
| Изолированные Node / npm | 24.18.0 / 11.16.0 | 24.22.1 / 11.19.1 |
| PyTorch | 2.10.0+cu130 | 2.10.0+cu130 |

Официальная команда `unsloth studio update` устанавливает совместимую смешанную ветку llama.cpp от Unsloth. Затем fastload копирует именно эти исходники, применяет существующий включаемый патч обхода RPC hash-cache, собирает CUDA/RDMA для host и worker, проверяет манифесты и переключает пару. Сохранены пользовательский launcher Q8 с долями 43:57 и контекстом 1048576, а также шлюз памяти Spark Link.

## Проверка на оборудовании

- Выбрана fastload-пара `b59492e60c9cb513b24176170f9ab83aa72b4cd0264d6c6df403d556bac5962e`. Оба устройства собрали одни исходники с GCC 13.3.0 и NVCC 13.0.88; CUDA и RDMA включены. Проверены манифесты host/worker и исполняемый файл работающего RPC.
- Небольшая кешированная Qwen выполнила генерацию на двух устройствах через независимый шлюз памяти на стандартной библиотеке Python. Применились сохранённые доли 45:55 и контекст 512 вместо устаревшего аргумента 8192.
- Исходная `unsloth/DeepSeek-V4-Flash-Vision-Exp-GGUF`, `UD-Q8_K_XL`, загрузилась через настоящий API Studio за **165,2 секунды**. Studio сообщила контекст **1048576** и **4 параллельных слота**. В аргументах сохранены `CUDA0,RPC0`, `43,57` и прямой RPC через ConnectX-7. В журнале подтверждены активация RDMA и размещение всех 44 слоёв на GPU.

| Фактическое размещение | Первый Spark | Второй Spark |
| --- | ---: | ---: |
| Буферы весов на GPU | 67303,34 МиБ (65,73 ГиБ) | 86052,51 МиБ (84,04 ГиБ) |
| Сумма KV-буферов по журналу | 11833 МиБ (11,56 ГиБ) | 15816 МиБ (15,45 ГиБ) |
| Доступная память ОС при загруженной модели, примерно | 27 ГиБ | 11 ГиБ |

Границы слоёв делают фактические пропорции приблизительными. Доступная память включает освобождаемый кеш и отличается от отдельного столбца `free`. На первом Spark остаётся больший запас.

OpenAI-совместимый маршрут чата Studio вернул **`4`** на `2+2` и **`Red`** на синтетическую полностью красную картинку. Оба HTTP-запроса завершились успешно. Проверка здоровья Studio продолжала отвечать HTTP 200. Модель выгружена через API Studio, процессов `llama-server` не осталось; доступная память вернулась примерно к 114/116 ГиБ. Тестовые планы памяти удалены.

Прошли существующие **132 теста CLI и 40 тестов приложения**; две проверки netplan отдельно выполнены системным Python Ubuntu. SHA-256 исходного пользовательского launcher остался `cddb6aec3304021e2a759cca302ed952c95b809eb422b59f6e4561859e4da59e`. Признак незавершённого обновления очищен, пользовательский linger включён.

Проверены короткие текстовый и визуальный запросы и выделение памяти под настроенный контекст. Заполнение окна миллионом токенов, генерация на трёх устройствах и отключение питания во время генерации здесь не проверялись. [Результат в JSON](runtime-validation-2026-10-31.json).

Первая попытка зависла при загрузке Node с nodejs.org на Spark. После её остановки автоматический откат вернул прежнюю среду и fastload-пару. Для повторной попытки официальный архив Node скачан на управляющем компьютере и временно передан через loopback-сервер на Spark; его SHA-256 проверен по закреплённой сумме из пакета Unsloth. Проверка контрольных сумм не отключалась. Временный источник не становится постоянной зависимостью среды.

Установщик сообщил об отсутствии совместимого wheel torchcodec для ARM64/Python 3.13 с этой версией Torch; декодирование аудио через TorchCodec остаётся недоступным. Эта проверка не подтверждает работу декодирования аудио/видео или обучения.

## Обновить существующую установку

В Spark Link выгрузите модели в Studio, затем выберите **Обновления → Обновить Studio и RPC**. Перед официальным updater и согласованной сборкой RPC приложение создаст локальную копию для отката.

Для независимой CLI на двух устройствах:

```bash
connect-dual-spark --lang ru update-unsloth
connect-dual-spark --lang ru status
connect-dual-spark --lang ru check
```

CLI и приложение управляют одной средой; запускайте одно обновление за раз. Для первой установки используйте [инструкцию приложения](../desktop/README.ru.md) или [инструкцию CLI](../README.ru.md).
