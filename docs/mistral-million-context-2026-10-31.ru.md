# Исправление запуска Mistral с контекстом 1M — Spark Link 1.4.1

Существующая Mistral Large 4 UD-IQ1_S теперь загружается через обычный API Studio на настоящем кластере из трёх Spark: **контекст 1048576, F16 KV, high reasoning и совместимый DSpark-драфт**. Текст и изображение проверены. Модель оставлена загруженной для работы.

## Причина

Первый запуск упёрся в рабочие буферы: третий worker не смог выделить 69,32 ГиБ, затем 18,98 ГиБ при повторе без конвейера. Одно уменьшение microbatch оставляло запросы 63,20 / 15,85 ГиБ. В карте общего KV-кэша модели поздние слои используют слой 35, а attention семи потребителей находился на другом RPC GPU. Копии полного кэша между устройствами и конвейер планировщика раздували память на миллионе токенов.

Повторный запуск останавливался ещё раньше в общей проверке памяти. Она предполагает линейное распределение весов и KV по заданным процентам и оставляет 24 ГиБ резерва на первом Spark. Для этой модели с общим кэшем и проверенным плотным размещением это давало неверный прогноз.

## Что исправлено

- Сохранены шесть существующих файлов весов, контекст 1048576, F16 K/V и high reasoning.
- Запрошены доли слоёв **27:34:39**, чтобы оставить больше места первому Spark.
- `blk.(47|51|55|59|63|67|71).attn_*` размещаются на `RPC0[10.100.32.2:50053]` рядом с общим KV-источником. FFN-веса остаются распределёнными. Меняется размещение, а не веса или математическая точность. Явное размещение тензоров также отключает затратный конвейер основной модели.
- Batch 128, microbatch 16, **одна параллельная очередь**, Flash Attention включён, автоматический fit отключён. Дополнительные RAM-копии промптов и checkpoints контекста отключены; активный миллионный KV-кэш сохраняется.
- Удержание RPC-графов отключается только для процесса этой модели. Настройки служб workers и других моделей сохраняются.
- Перед общей линейной оценкой применяется локально проверенный профиль. Он сверяет заголовок/размеры частей модели, хэш движка, RPC-манифесты, порядок устройств, адреса и измеренную память каждого узла плюс 4 ГиБ резерва. Изменение движка/модели и нехватка RAM останавливают запуск до выделения памяти. Явные пользовательские планы памяти сохраняют приоритет.

Профиль является локальной настройкой этого кластера, а не универсальным неподтверждённым пресетом для другого оборудования или квантования. Код включён в независимый runtime моделей и приложение; закрытие GUI не убирает исправление.

## Проверка

Рабочий буфер основной модели на третьем Spark теперь составляет около **2,35 ГиБ**. Кэш основной модели остаётся **83840 МиБ (81,875 ГиБ)**, дополнительно есть небольшой кэш драфта. Заявленный контекст 1M не сокращался.

В отдельном прогоне обработан ввод на 1836 токенов с текстовым наполнителем и арифметикой, получен ответ `4`. Красное тестовое изображение дало `Red`; использовался high reasoning. Затем **обычный запуск из Studio**, запрошенный с четырьмя слотами, применил проверенную одну очередь и повторно прошёл текст/изображение. Это проверка выделения контекста и реальных запросов, а не заполненного миллионом токенов входа или полноценной оценки качества.

Синтетическое продолжение числового ряда выдало 128 токенов со скоростью около 12,2 ток/с. Это не прогноз скорости обычного чата. Меньший пакет и одна очередь обменивают скорость prefill/параллелизм на запас памяти.

Пройдены 138 тестов CLI и все 65 проверок приложения в изолированном/системном Python: привязка профиля, отказ после изменения движка, сохранение точности, отказ при нехватке RAM и запрет непроверенного CPU-offload. Службы всех трёх устройств оставались активны. Драйвер CUDA, веса и квантование KV не менялись.

Практические ограничения: для этого режима 1M/F16 нужны все три настроенных Spark; другие тяжёлые приложения могут съесть необходимую свободную RAM; после обновления движка/модели профиль нужно перепроверить. Явный ручной план памяти может переопределить автоматический выбор профиля.
